A
How a PC Boots — Essential Background
Required reading before everything else
▼

When you press the power button on an x86 PC, a precise sequence of events unfolds before your OS kernel ever runs a single instruction.

  1. The CPU resets and starts executing at physical address 0xFFFFFFF0 — the very top of 32-bit address space — where the BIOS ROM is mapped.
  2. The BIOS runs its POST (Power-On Self-Test): checks RAM, discovers hardware, and sets up the Interrupt Vector Table (IVT) at address 0x0000.
  3. The BIOS finds a bootable disk, reads the first 512-byte sector (the MBR) into address 0x7C00, checks for the boot signature 0x55 0xAA, and jumps to 0x7C00.
  4. The CPU is in REAL MODE (16-bit). Only the first 1 MB of RAM is accessible and BIOS interrupts are available.
  5. Our boot.asm runs from 0x7C00. It loads the kernel, switches to PROTECTED MODE (32-bit), and jumps to the kernel at 0x10000.
  6. Our kernel_main() takes over. The BIOS is gone. The kernel manages everything itself.

boot.asm — Line by Line
16-bit bootloader · real mode → protected mode transition
▼
Overview
The bootloader is exactly 512 bytes. It runs in 16-bit real mode, loads the kernel from disk, sets up the GDT, and switches the CPU into 32-bit protected mode.
Initialization
[BITS 16]
[ORG 0x7C00]
start:
BITS 16 tells NASM to emit 16-bit machine code (CPU starts in real mode).
ORG 0x7C00 tells NASM the code loads at physical address 0x7C00, making all label addresses correct relative to that base.
start: The entry point label. Execution begins here after the BIOS jumps to 0x7C00.
cli
xor ax, ax
mov ds, ax
mov es, ax
mov ss, ax
cli disables maskable interrupts while we set up the stack.
xor ax, ax sets AX=0 (faster/smaller than "mov ax, 0" and sets the Zero Flag).
mov ds, ax, mov es, ax mov ss, ax
In real mode, memory addresses are formed as (segment × 16 + offset). Setting DS (Data Segment), ES (Extra Segment) and SS (Stack Segment) all to zero means we use a "flat" model where (segment × 16 = 0), so effective addresses equal their offsets. This avoids unexpected aliasing bugs.
mov sp, 0x7C00
sti
mov sp, 0x7C00 Stack pointer at 0x7C00 — the stack grows DOWNWARD, so the first PUSH writes to 0x7BFE, safely below the bootloader. The stack won't collide with us until it gets very large
sti "Set Interrupt Flag" — re-enable interrupts. The stack is now valid, so BIOS interrupt service routines are safe to call.
mov [boot_drive], dl
mov si, msg_loading
call print_string
mov [boot_drive], dl When the BIOS calls our bootloader it puts the drive number (0x00 = floppy, 0x80 = first hard disk) in DL. We save it to the variable boot_drive so we can use it later when reading more sectors.
mov si, msg_loading call print_string Load the address of our "Loading kernel..." string into SI (Source Index), then call our print routine. SI is the pointer register used by LODSB.
Disk Read (BIOS INT 0x13)
mov ax, 0x1000
mov es, ax
xor bx, bx
mov ah, 0x02
mov al, 63
mov ch, 0
mov cl, 2
mov dh, 0
mov dl, [boot_drive]
int 0x13
jc disk_error
mov ax, 0x1000 mov es, ax xor bx, bx
Set up the destination for the disk read: ES:BX = 0x1000:0x0000. In real-mode segmentation this resolves to physical address 0x10000. This is exactly where our kernel will be loaded and where the linker script places it.
mov ah, 0x02 BIOS INT 0x13 function 0x02 = "Read Sectors From Drive".
mov al, 16 Read 16 sectors = 16 × 512 = 8192 bytes. That's plenty for our kernel. If your kernel grows, increase this number (max ~63 for a floppy layout).
mov ch, 0 Cylinder 0 (the first cylinder on the disk).
mov cl, 2 Starting sector 2 (sectors are 1-indexed; sector 1 is the boot sector itself).
mov dh, 0 Head 0 (the first read/write head).
mov dl, [boot_drive] The drive number we saved earlier.
int 0x13 Call the BIOS disk interrupt. On return: CF (Carry Flag) is set on error.
jc disk_error "Jump if Carry" — if the read failed, jump to our error handler.
Entering Protected Mode
cli
lgdt [gdt_descriptor]
mov eax, cr0
or eax, 0x1
mov cr0, eax
jmp 0x08:protected_mode_start
cli Disable interrupts again before entering protected mode. Real-mode BIOS ISRs are not valid in protected mode; we must not let them fire during the switch.
lgdt [gdt_descriptor] "Load Global Descriptor Table Register" — tells the CPU where our GDT is. The GDTR register is 6 bytes: 2-byte limit + 4-byte base address.
mov eax, cr0 or eax, 0x1 mov cr0, eax
CR0 bit 0 is the Protection Enable (PE) bit. Setting it switches the CPU from real mode to protected mode. We must immediately do a far jump to flush the instruction pipeline (the CPU may have pre-fetched real-mode instructions).
jmp 0x08:protected_mode_start A FAR JUMP to segment 0x08 (code segment selector in the GDT), offset protected_mode_start. The CPU loads CS with 0x08 and reloads the instruction pipeline with 32-bit protected-mode decoding. From this point forward we are in 32-bit protected mode.
GDT — Global Descriptor Table
What is the GDT?
The GDT defines memory segments for protected mode. Each 8-byte entry describes a segment's base address, limit, and access rights. The CPU requires the first entry to be a null descriptor.

gdt_code (selector 0x08)

Base 0, Limit 4 GB, ring 0, executable, readable.
Bit flags: Present=1, DPL=0, Executable=1, 32-bit, 4KB granularity.

gdt_data (selector 0x10)

Same as code but Executable=0 (data segment), writable.
Used for DS, ES, SS, FS, GS inside the kernel.

print_string Subroutine
print_string:
 pusha
pusha Save all general-purpose registers to the stack. PUSHA pushes AX, CX, DX, BX, SP, BP, SI, DI in that order.
.loop:
 lodsb
 or al, al
 jz .done
 mov ah, 0x0E
 mov bh, 0x00
 mov bl, 0x07
 int 0x10
 jmp .loop
lodsb "Load String Byte" — loads the byte at [DS:SI] into AL and increments SI. This auto-advances the pointer through our string.
or al, al Bitwise OR of AL with itself. This doesn't change the value but sets the Zero Flag if AL == 0 (which is our NUL terminator).
jz .done If AL was 0 (end of string), jump to .done.
mov ah, 0x0E BIOS INT 0x10 function 0x0E = "Teletype Output" (write one character).
mov bh, 0x00 Page 0 (the current display page, usually page 0).
mov bl, 0x07 Foreground colour attribute (light grey on black) in some BIOS implementations.
INT 0x10 / AH=0x0E Call BIOS video interrupt to print the character in AL.
jmp .loop Repeat for the next character.
.done:
 popa
 ret
popa Restore all registers we saved with PUSHA.
ret Return to the caller.
asm — boot signature
times 510-($-$$) db 0   ; pad sector to 510 bytes
dw 0xAA55               ; boot signature (stored little-endian as 55 AA)
Important
After protected_mode_start, all segment registers (DS, ES, SS, FS, GS) are loaded with the data selector 0x10. The stack moves to 0x90000. Then call 0x10000 jumps to the kernel.
C
linker.ld — Linker Script
Controls how sections are laid out in memory
▼
linker script
ENTRY(kernel_main)

SECTIONS {
    /* load address — must match bootloader's call 0x10000 */
    . = 0x10000;

    .text   : { *(.text)   }    /* compiled code (kernel_main lives here) */
    .rodata : { *(.rodata) }    /* string literals, const globals */
    .data   : { *(.data)   }    /* initialised global/static variables */
    .bss    : { *(.bss) *(COMMON) }  /* zero-initialised globals (IDT array) */
}
. = 0x10000;
The location counter sets the Virtual Memory Address for every section. We start at 0x10000 because that's where boot.asm loads and jumps to kernel.bin. Physical addresses equal VMAs because paging is not enabled.
.bss : { *(.bss) *(COMMON) }
The BSS section holds uninitialized globals. The bootloader does not zero it for us — we call k_memset in idt_install() to zero the 256-entry IDT array before use.
Why objcopy?
The linker produces an ELF file. We strip ELF headers with objcopy -O binary to get a raw binary. The BIOS disk read loads raw bytes — it cannot parse ELF format.

§1 Port I/O Helpers
x86 I/O Address Space
x86 has a separate I/O address space accessed via IN/OUT instructions — not regular memory reads/writes. PIC, PIT, keyboard, VGA all live here.
outb(port, value)
inb(port) → value
io_wait()
outb/inb use inline assembly with volatile to prevent compiler optimisation. The "dN" constraint uses DX register or immediate for port numbers.
io_wait() writes to port 0x80 (POST diagnostic port) — a harmless ~1-4µs delay for slow hardware like the 8259A PIC.
§2 VGA Text-Mode Driver

0xB8000 — VGA Buffer

Memory-mapped framebuffer. Each of 2000 cells is 2 bytes: low byte = ASCII character, high byte = color attribute.

80×25 Grid

16 foreground colors, 8 background colors.
Attribute = (bg << 4) | fg.
Hardware cursor controlled via ports 0x3D4/0x3D5.

vga_scroll()
vga_putchar(c)
vga_update_cursor()
vga_scroll() uses memmove to shift rows 1–24 up by one row, then fills the last row with spaces.
vga_putchar() handles \n, \r, \b and wraps columns/rows automatically.
§3 String & Number Utilities

No libc — we implement only what we need: k_strlen, k_strcmp, k_strncmp, k_strcpy, k_itoa (unsigned int → decimal string), and k_memset (used to zero the IDT).

§5 Interrupt Descriptor Table (IDT)
How Interrupts Work
When an interrupt fires, the CPU reads the 8-byte IDT entry for that vector, jumps to the ISR address stored in it, and automatically pushes EFLAGS, CS, EIP (and an error code for some exceptions) onto the stack.
c — IDT entry structure
typedef struct __attribute__((packed)) {
    uint16_t offset_lo;  // ISR address bits [15:0]
    uint16_t selector;   // code segment = 0x08
    uint8_t  zero;       // reserved, must be 0
    uint8_t  type_attr;  // 0x8E = present, ring0, 32-bit interrupt gate
    uint16_t offset_hi;  // ISR address bits [31:16]
} idt_entry_t;
type_attr = 0x8E = 1000_1110b
Bit 7 (P)=1 gate present. Bits 6-5 (DPL)=00 ring 0 only. Bit 4=0 not storage segment. Bits 3-0=1110 = 32-bit interrupt gate. An interrupt gate automatically clears IF (disables further interrupts on entry).
§6 ISR Stub Macros
__attribute__((naked))
STUB_ISR_NOERR(n):
cli;
push $0;
push $n
pusha
push %ds
→ call isr_handler(regs)
← pop %ds; popa
add $8, %esp
iret
A naked function has no compiler-generated prologue/epilogue — we control the stack entirely. We push a fake error code (0) so all exceptions have the same stack layout. We push ESP as the argument to isr_handler — it points to our registers_t on the stack. IRET restores EIP, CS, EFLAGS.
§7 PIC — Programmable Interrupt Controller
Why Remap?
The 8259A PIC's default IRQ0–IRQ7 map to vectors 0x08–0x0F — which collide with CPU exception vectors 8–15. We remap IRQs to vectors 0x20–0x2F (safe, above all 32 exceptions).
Master PIC: IRQ0-7 → 0x20-0x27
Slave PIC: IRQ8-15 → 0x28-0x2F
ICW1: 0x11 (init, cascade)
ICW2: offset vectors
ICW3: cascade identity
ICW4: 0x01 (8086 mode)
The 8259A is initialized with four Initialization Command Words (ICW). After remapping: IRQ0=timer (vec 32), IRQ1=keyboard (vec 33), IRQ8–15 on slave. EOI (0x20) must be sent to the PIC after every IRQ handler or no further interrupts of that type will fire.
§8 Timer (IRQ 0)
volatile uint32_t timer_ticks = 0;
irq_handler_timer() {
timer_ticks++;
pic_eoi(0);
}
volatile is critical — this variable is modified in an ISR and read in normal code. Without it, the compiler may cache it in a register and never re-read from memory. The PIT fires IRQ0 at ~18.2 Hz by default. Dividing by 18 gives approximate seconds.
§9 Keyboard (IRQ 1) — PS/2 Scancode Set 1

Scancode vs ASCII

Scancodes are hardware key codes from the keyboard matrix. E.g., scancode 0x1E = the 'A' key. We look up ASCII via kb_map[] or kb_map_shift[].

Ring Buffer

ISR writes to kb_buf[kb_head], shell reads from kb_buf[kb_tail]. Standard lock-free single-producer/single-consumer queue.

char kb_getchar() {
while (kb_head == kb_tail)
__asm__ volatile("hlt");
}
hlt halts the CPU until the next interrupt. This is power-efficient — instead of a busy-spin consuming 100% CPU, we sleep until the keyboard ISR advances kb_head. Break codes (key-release) have bit 7 set (0x80) — we ignore these.
§14 Shell

A minimal REPL (Read-Eval-Print Loop). The prompt myos@kernel:~$ is printed in multiple colors. Line editing supports backspace. Commands are dispatched via k_strcmp. cmd_reboot() sends 0xFE to PS/2 controller port 0x64 — this pulses the CPU RESET line for a hardware reset.

§15 Kernel Entry Point
c — kernel_main()
void kernel_main(void) {
    pic_remap();        // MUST be first — remap before enabling interrupts
    idt_install();      // fill 256 IDT gates, load IDTR
    __asm__ volatile("sti");  // interrupts are LIVE from here

    draw_banner();      // splash screen
    delay_ticks(18 * 2);  // ~2 second wait
    kb_getchar();       // or press any key

    vga_clear();
    shell_run();        // never returns

    __asm__ volatile("cli; hlt");  // safety net
}

Makefile — Build System

makefile — compiler flags
CFLAGS = -m32 -ffreestanding -fno-stack-protector \
         -nostdlib -O2 -Wall -Wextra -std=c11
-m32
Generate IA-32 (32-bit x86) machine code, regardless of host architecture.
-ffreestanding
No hosted environment assumed. Disables implicit standard headers. Allows __asm__, removes assumptions about main().
-fno-stack-protector
Disables stack canary — it requires __stack_chk_fail from libc, which we don't have.
-nostdlib
Don't link any standard libraries (no libc, no libgcc startup). Everything comes from our code only.
Building the Disk Image
dd if=/dev/zero of=os.img bs=512 count=2880
Create a 1.44 MB floppy image (2880 × 512 bytes) filled with zeros. This is the blank disk we'll write boot and kernel sectors into.
dd if=boot.bin of=os.img bs=512 count=1 conv=notrunc
Write the 512-byte boot sector to sector 1. conv=notrunc prevents truncating the output file after writing — preserving the rest of the image.
dd if=kernel.bin of=os.img bs=512 seek=1 conv=notrunc
seek=1 skips 1 block (512 bytes) before writing — placing the kernel at sector 2, exactly where boot.asm reads from (cylinder 0, head 0, sector 2).

Graphics — VESA/VBE Framebuffer
Switching from text mode to pixel-based drawing
▼

Current: VGA Text Mode

80×25 cells at 0xB8000. CPU writes char+attribute pairs. Hardware does font rendering. Fast, no driver complexity.

Goal: Linear Framebuffer

800×600 or 1024×768 at 24/32 bpp. Every pixel individually addressable. Required for GUI, images, custom fonts.

Option 1 — VESA BIOS Extensions (Recommended)
Critical
VBE must be called before entering protected mode — while still in real mode — because VBE uses INT 0x10 BIOS calls.
  1. Set VBE mode: INT 0x10, AX=0x4F02, BX=(mode | 0x4000). Mode 0x118 = 1024×768×24bpp, 0x115 = 800×600×24bpp. Bit 14 enables the Linear Framebuffer (LFB).
  2. Query mode info: INT 0x10, AX=0x4F01, CX=mode fills a VbeModeInfo struct with PhysBasePtr, Pitch, XResolution, YResolution, BitsPerPixel.
  3. Save PhysBasePtr, Pitch, Width, Height (e.g. at 0x9000) before jumping to protected mode, then read them in the kernel.
c — put_pixel()
uint8_t *fb = (uint8_t *)physBasePtr;

void put_pixel(int x, int y, uint32_t color) {
    uint32_t offset = y * pitch + x * (bpp / 8);
    fb[offset + 0] = color & 0xFF;          // Blue
    fb[offset + 1] = (color >> 8) & 0xFF;  // Green
    fb[offset + 2] = (color >> 16) & 0xFF; // Red
}
Option 2 — Bochs VBE Extensions (BGA)

QEMU emulates the Bochs Graphics Adapter. Set resolution/bit-depth by writing to I/O ports 0x01CE (index) and 0x01CF (data) directly from protected mode — no BIOS call needed. Simpler for development but won't work on real hardware.

PSF Bitmap Fonts

Download a PC Screen Font (.psf) from /usr/share/consolefonts/. Each glyph is 16 rows × 8 bits. To draw character 'A' at (x, y): iterate each row and bit, call put_pixel with foreground or background color based on whether the font bit is set.

Shell — Building a Real Interactive Shell
History · tab completion · argument parsing · pipes · env vars
▼
1. Command History

Keep a circular array of the last N command strings. On arrow-up/arrow-down (scancodes 0x48, 0x50), recall previous commands. Erase the current line (backspace to column 0), then print the historic command.

2. Tab Completion

On scancode 0x0F (Tab), look at the current partial input and find commands that start with it. If exactly one match, complete it. If multiple matches, print them as options (like bash).

3. argc/argv Parsing
c — tokenize command line
char *argv[16]; int argc = 0;
char *p = cmd_buf;
while (*p) {
    while (*p == ' ') p++;        // skip spaces
    if (*p) argv[argc++] = p;     // start of token
    while (*p && *p != ' ') p++; // find end
    if (*p) *p++ = '\0';         // NUL-terminate
}
4 & 5. Pipes, Redirection, Environment Variables
Design Note
True piping requires multiple concurrent processes sharing a buffer — which needs multitasking. Environment variables can be implemented as a simple key-value store: an array of "KEY=VALUE" strings with get_env()/set_env() helpers.

Keyboard & Mouse — Full PS/2 Driver
Extended scancodes · Caps Lock · Scan Code Set 2 · PS/2 mouse IRQ12
▼
Keyboard Improvements
Extended scancodes:
0xE0 prefix → next byte = ext key
Caps Lock: toggle on make-code, track state
Many keys (arrows, Home, End, Insert, Delete, F5–F12) send 2-byte sequences: 0xE0 followed by a second scancode. Detect 0xE0 in the ISR, set a flag, and use a separate extended-key table for the next scancode.
Adding PS/2 Mouse (IRQ 12)
  1. Send command 0xA8 to port 0x64 (enable mouse port), then 0xD4 + 0xF4 to activate streaming mode.
  2. Install an IDT gate for vector 44 (IRQ12 = 32+12). The mouse sends 3-byte packets: status byte, X movement (signed), Y movement (signed, Y inverted vs screen).
  3. In text mode: draw cursor by inverting the attribute byte at the current mouse cell. In graphics mode: blit a small bitmap at (mouse_x, mouse_y), redraw background on move.
Mouse Button Bits (Byte 0)
Bit 0 = left button · Bit 1 = right button · Bit 2 = middle button

System Commands — ls, cd, cat via FAT12
FAT12 filesystem layout · directory entries · cluster chain parsing
▼
Prerequisite
Commands like ls, cat, cd require a filesystem. FAT12 (used on 1.44 MB floppies) is the simplest real filesystem to implement.
FAT12 Disk Layout
SectorsContents
0Boot sector (BPB + boot code)
1–9FAT copy 1 (allocation table)
10–18FAT copy 2 (redundant)
19–32Root directory (224 entries max)
33+Data clusters (cluster 2 = sector 33)
FAT12 Cluster Entry Decoding
c — read FAT12 entry N
// FAT12: 12-bit entries, 3 bytes encode 2 entries
if (N % 2 == 0)
    entry = fat[N*3/2] | ((fat[N*3/2+1] & 0x0F) << 8);
else
    entry = (fat[N*3/2] >> 4) | (fat[N*3/2+1] << 4);

// 0x000 = free cluster
// 0xFF8-0xFFF = end of file
// else = next cluster number
Shell Commands via FAT12
ls
Read the root directory table. Print all entries where attr != 0 and name[0] != 0xE5 (deleted). Show name, size, date.
cat filename
Find the file's DirEntry, follow the cluster chain through the FAT, read each cluster's data bytes, print to screen.
cd dirname
FAT12 subdirectory entries have attr = 0x10. Read the directory cluster for the target dir. Keep a "current directory" cluster number in a global variable.
Ramdisk Approach (Easier for Development)
Pass -initrd myfiles.img to QEMU. In the kernel, parse the Multiboot info structure to find the ramdisk's physical address and size, then parse FAT12 directly from that RAM buffer — no disk driver needed.

Useful QEMU Flags
-s / -S
-s shorthand for -gdb tcp::1234. -S freezes the CPU at startup, waiting for GDB to connect before executing any instructions.
-m 32M -vga std -display curses -nographic
Set VM RAM. -vga std needed for VBE modes. -display curses uses text-mode display for SSH sessions. -nographic disables the window entirely — serial only.

Why GRUB?
Using GRUB as the bootloader gives you Multiboot support, memory map discovery, and the ability to load modules (ramdisk) for free — without writing any of it yourself.
